0API 统一规则#

0.1 Getter 与 Setter#

绝大多数属性使用同名重载。无参数版本读取值，带参数版本设置值并返回当前对象，因此可以链式调用：

C++
auto label = a.UI.AddLabel("你好")    .FontSize(32)    .TextColor(Colors.Blue)    .Size(300, 60); float fontSize = label.FontSize();

本手册在属性表中只列一次属性名。除非特别说明，每个属性都同时代表：

C++
Type Name() const;                  // 读取Owner Name(const Type& value) const; // 设置并返回当前对象

0.2 重复参数与返回规则#

  • std::string_view：传入 UTF-8 文本或资源路径；ToyCode 会在调用期间复制必要内容。
  • bool：表示功能开关。
  • float seconds：以秒为单位，允许小数。
  • Color：RGBA 颜色；Alpha() 返回修改透明度后的新颜色。
  • 返回控件或对象的 Setter：用于链式调用。
  • 返回 bool：成功为 true，参数、句柄或资源无效时为 false。
  • 返回 std::size_t：数量、字节数、缓存数或实际处理数。
  • 对象变量是轻量句柄；父容器负责底层对象生命周期。

0.3 资源、纹理和音频的职责#

C++
a.Assets;   // 文件、ZIP、实际来源和原始字节a.Textures; // 二维图片的预加载、显存缓存和清理a.Audio;    // 音量、播放控制、音频预解码与PCM缓存

同一规范化路径只保存一份纹理或 PCM 数据。多个 Image、Sprite、Sound 可以共享底层缓存，同时保留各自的位置、颜色、音量和播放状态。

2坐标、尺寸与生命周期#

2.1 坐标系#

ToyCode 使用适合 UI 和 2D 游戏的坐标系：

  • 原点 (0, 0) 在左上角。
  • X 向右增加。
  • Y 向下增加。
  • Position 默认表示对象左上角的位置。
C++
auto image = a.AddImage("hero.png");image.Position({100, 80});

2.2 图片的默认尺寸#

图片文件本身带有宽高。AddImage("hero.png") 会读取资源的原始分辨率，不必手工填写尺寸。只有希望拉伸或布局约束时才设置 Size：

C++
auto image = a.AddImage("hero.png");auto natural = image.Size(); float width = natural.Width;float height = natural.Height; image.Size({320, 180});

2.3 自动内存管理#

ToyCode 的界面和场景对象形成父子树：

  • a.UI.AddButton() 创建的按钮归 a 所有。
  • panel.AddImage() 创建的图片归 panel 所有。
  • 父对象销毁时，它的子对象也会销毁。
  • 普通代码不需要 delete，也不需要逐个 Dispose()。
  • 只有需要提前删除对象时才调用 Dispose()。
C++
auto panel = a.AddBox();auto icon = panel.AddImage("icon.png"); // 提前销毁 panel 时，icon 一起销毁。panel.Dispose();

对象变量本身是轻量句柄。IsValid() 判断句柄是否有效，IsDisposed() 判断底层对象是否已经销毁。

32.7.30 的统一 Get/Set 语法#

ToyCode 2.7.30 使用同名函数完成读取和设置：

C++
label.Text("你好");       // setterlabel.FontSize(32);       // setter std::string text = label.Text(); // getterfloat size = label.FontSize();   // getter

Setter 返回当前对象，所以可以链式书写：

C++
auto label = a.UI.AddLabel("你好")    .FontSize(32)    .TextColor(Colors.Blue)    .Position({30, 40})    .Size({300, 60});

以下是旧设计或错误写法，不要在 2.7.30 中使用：

C++
// 错误：属性不再用等号设置label.Text = "你好"; // 错误：不再使用 Get()auto value = label.Size.Get(); // 正确label.Text("你好");auto value = label.Size();

事件、集合和功能入口保留成员形式：

C++
button.Click([](ClickArgs e){});combo.Items.Add("第一项");box.UI.AddLabel("文字");box.Shape.AddCircle(80);box.Action.MoveBy({100, 0}, 0.5F).Do();box.Body.Velocity({200, 0});

7布局系统#

7.1 为什么优先使用布局#

固定坐标适合游戏场景；应用界面更适合布局。布局能自动处理文字尺寸、窗口缩放和内容增减。

7.2 VStack 与 HStack#

C++
auto form = a.AddVStack()    .Width(560)    .Padding(32)    .Spacing(18)    .CornerRadius(28)    .Background(Colors.White)    .Align(Align.Center); form.UI.AddLabel("创建账户").FontSize(38);form.UI.AddTextBox("请输入名字").Width(496);form.UI.AddTextBox("请输入密码").Width(496).Password(true);form.UI.AddButton("确定").Width(496);

VStack 纵向排列，HStack 横向排列。

7.3 Padding、Margin、Spacing#

  • Padding：容器边缘与内部子元素之间的留白。
  • Margin：当前对象与外部相邻对象之间的留白。
  • Spacing：同一容器内相邻子元素之间的统一距离。
C++
auto row = a.AddHStack().Padding(20).Spacing(12);row.UI.AddButton("取消").Margin({0, 0, 8, 0});row.UI.AddButton("保存");

7.4 对齐 Align#

C++
label.Align(Align.Center);button.Align(Align.Right);panel.Align(Align.Fill);

可用值：Free、TopLeft、Top、TopRight、Left、Center、Right、BottomLeft、Bottom、BottomRight、Fill。

规则建议：

  • Align != Free 时，让布局系统决定最终位置。
  • 需要完全自由定位时使用 Align.Free 和 Position()。
  • 不要同时依赖相互冲突的布局约束。

7.5 Grid#

C++

  • 数字：固定像素。
  • Auto：按内容需要。
  • *：分配剩余空间。
  • 2*：获得普通 * 两倍的剩余份额。

搜索原则：

  1. 独立文件与 zip 可以并存。
  2. zip 文件名不固定，可以登记多个。
  3. 调用时仍只写逻辑资源名。
  4. zip 内应直接包含资源或保持调用时所写的相对路径；不要无意多压一层目录。

开发期可使用独立文件方便替换，发布时再整理到 zip。

31.2 调试信息#

31.3 性能原则#

  • 重复图片/精灵共用纹理缓存，不要为每颗子弹生成不同文件。
  • 图集减少纹理切换；同材质、同纹理对象更容易批处理。
  • 不要让每颗子弹对每个敌人手动调用 IsColliding。
  • 静态 UI 不要每帧重设同一属性。
  • Surface.UpdateRegion 优于每次上传整张大画布。
  • 大量文本、阴影、模糊、发光会增加渲染成本。
  • Debug 的 17 FPS 与 Release 的数百 FPS 不能直接比较。

37常见问题#

Q1：为什么 a. 后没有函数提示？#

确认包含的是当前 ToyCode.h，项目语言标准为 C++17，并重新扫描 IntelliSense。不要同时引用旧版本头文件。

Q2：为什么 Debug 很慢，Release 很快？#

Debug 含检查且优化关闭。性能测试必须用 Release x64；Debug 主要用于断点和错误定位。

Q3：图片、声音明明存在却加载失败？#

先确认文件在 Game.exe 的工作目录，例如 x64/Debug。如果在 zip 中，确认已 AddZip，且 zip 内没有意外多一层目录。

Q4：程序提示缺少 DLL？#

运行目录至少需要当前动态链接版本的 ToyCode.dll、SDL3.dll、SDL3_ttf.dll。Debug/Release、x64/x86 不可混用。

Q5：为什么文字模糊或粗体不好看？#

优先提供字体家族的真实 Bold/Italic 字体文件；同时检查窗口缩放和虚拟分辨率是否造成非整数缩放。

Q6：Position 和布局会冲突吗？#

会参与同一最终布局。自由游戏对象使用 Align.Free + Position；普通 UI 尽量使用 Align、Margin、Padding、Spacing 和 Grid。

Q7：事件中的 e. 为什么没有 IntelliSense？#

按钮点击可把 auto e 改成明确的 ClickArgs e。其他事件参数常与发送者类型相关，当前可继续使用 auto e；IDE 代码片段可直接补全事件体中最常用的字段。

Q8：关闭窗口后进程不退出怎么办？#

确认没有混用错误版本 DLL，并检查清理阶段是否卡在音频或第三方库。当前正确版本会让 Run() 返回并正常完成析构。

Q9：能否发布到 Web 或 APK？#

核心设计为跨平台 C++，但一键 Web/APK 打包链仍属于后续工具链工作，不能把 Windows DLL 直接变成网页或 APK。

Q10：3D 是否等于完整大型引擎？#

不是。当前目标是核心内的易学轻量 3D；大型资产管线、骨骼动画、复杂物理和编辑器将逐步补充。

41给其他 AI 的强制生成约束#

  1. 只包含 <ToyCode.h>，使用 using namespace toy;。
  2. 程序入口从 App a("标题"); 开始，以 return a.Run(); 结束。
  3. 属性使用 Name(value) 设置、Name() 读取，不生成 SetName()、.Get() 或属性赋值语法。
  4. UI 优先使用 VStack、HStack、Grid、Align、Margin、Padding 和 Spacing，不要为常规界面手算大量坐标。
  5. 事件使用 button.Click([=](ClickArgs e) { ... });；不确定事件参数类型时可以使用 auto e。
  6. 图片与动画使用 AddImage、AddSprite、AddTileMap；不要自行调用 SDL API。
  7. 文件与 ZIP 使用 a.Assets；纹理缓存使用 a.Textures；音频缓存和播放使用 a.Audio，不要创造 a.Resources。
  8. 普通对象由父容器自动管理。只有确实需要提前移除对象时才调用 Dispose()。
  9. 同一图片或音效会自动共享缓存。正式关卡可使用 Textures.Preload() 与 Audio.Preload() 消除首次使用停顿。
  10. 代码遵循 C++17、Allman 大括号风格，并尽量保持一条语句不进行无意义折行。
