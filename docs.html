0API 统一规则#

0.1 Getter 与 Setter#

绝大多数属性使用同名重载。无参数版本读取值，带参数版本设置值并返回当前对象，因此可以链式调用：

C++
auto label = a.UI.AddLabel("你好")    .FontSize(32)    .TextColor(Colors.Blue)    .Size(300, 60); float fontSize = label.FontSize();

本手册在属性表中只列一次属性名。除非特别说明，每个属性都同时代表：

C++
Type Name() const;                  // 读取Owner Name(const Type& value) const; // 设置并返回当前对象

0.2 重复参数与返回规则#

  • std::string_view：传入 UTF-8 文本或资源路径；ToyCode 会在调用期间复制必要内容。
  • bool：表示功能开关。
  • float seconds：以秒为单位，允许小数。
  • Color：RGBA 颜色；Alpha() 返回修改透明度后的新颜色。
  • 返回控件或对象的 Setter：用于链式调用。
  • 返回 bool：成功为 true，参数、句柄或资源无效时为 false。
  • 返回 std::size_t：数量、字节数、缓存数或实际处理数。
  • 对象变量是轻量句柄；父容器负责底层对象生命周期。

0.3 资源、纹理和音频的职责#

C++
a.Assets;   // 文件、ZIP、实际来源和原始字节a.Textures; // 二维图片的预加载、显存缓存和清理a.Audio;    // 音量、播放控制、音频预解码与PCM缓存

同一规范化路径只保存一份纹理或 PCM 数据。多个 Image、Sprite、Sound 可以共享底层缓存，同时保留各自的位置、颜色、音量和播放状态。

2坐标、尺寸与生命周期#

2.1 坐标系#

ToyCode 使用适合 UI 和 2D 游戏的坐标系：

  • 原点 (0, 0) 在左上角。
  • X 向右增加。
  • Y 向下增加。
  • Position 默认表示对象左上角的位置。
C++
auto image = a.AddImage("hero.png");image.Position({100, 80});

2.2 图片的默认尺寸#

图片文件本身带有宽高。AddImage("hero.png") 会读取资源的原始分辨率，不必手工填写尺寸。只有希望拉伸或布局约束时才设置 Size：

C++
auto image = a.AddImage("hero.png");auto natural = image.Size(); float width = natural.Width;float height = natural.Height; image.Size({320, 180});

2.3 自动内存管理#

ToyCode 的界面和场景对象形成父子树：

  • a.UI.AddButton() 创建的按钮归 a 所有。
  • panel.AddImage() 创建的图片归 panel 所有。
  • 父对象销毁时，它的子对象也会销毁。
  • 普通代码不需要 delete，也不需要逐个 Dispose()。
  • 只有需要提前删除对象时才调用 Dispose()。
C++
auto panel = a.AddBox();auto icon = panel.AddImage("icon.png"); // 提前销毁 panel 时，icon 一起销毁。panel.Dispose();

对象变量本身是轻量句柄。IsValid() 判断句柄是否有效，IsDisposed() 判断底层对象是否已经销毁。

32.7.30 的统一 Get/Set 语法#

ToyCode 2.7.30 使用同名函数完成读取和设置：

C++
label.Text("你好");       // setterlabel.FontSize(32);       // setter std::string text = label.Text(); // getterfloat size = label.FontSize();   // getter

Setter 返回当前对象，所以可以链式书写：

C++
auto label = a.UI.AddLabel("你好")    .FontSize(32)    .TextColor(Colors.Blue)    .Position({30, 40})    .Size({300, 60});

以下是旧设计或错误写法，不要在 2.7.30 中使用：

C++
// 错误：属性不再用等号设置label.Text = "你好"; // 错误：不再使用 Get()auto value = label.Size.Get(); // 正确label.Text("你好");auto value = label.Size();

事件、集合和功能入口保留成员形式：

C++
button.Click([](ClickArgs e){});combo.Items.Add("第一项");box.UI.AddLabel("文字");box.Shape.AddCircle(80);box.Action.MoveBy({100, 0}, 0.5F).Do();box.Body.Velocity({200, 0});

7布局系统#

7.1 为什么优先使用布局#

固定坐标适合游戏场景；应用界面更适合布局。布局能自动处理文字尺寸、窗口缩放和内容增减。

7.2 VStack 与 HStack#

C++
auto form = a.AddVStack()    .Width(560)    .Padding(32)    .Spacing(18)    .CornerRadius(28)    .Background(Colors.White)    .Align(Align.Center); form.UI.AddLabel("创建账户").FontSize(38);form.UI.AddTextBox("请输入名字").Width(496);form.UI.AddTextBox("请输入密码").Width(496).Password(true);form.UI.AddButton("确定").Width(496);

VStack 纵向排列，HStack 横向排列。

7.3 Padding、Margin、Spacing#

  • Padding：容器边缘与内部子元素之间的留白。
  • Margin：当前对象与外部相邻对象之间的留白。
  • Spacing：同一容器内相邻子元素之间的统一距离。
C++
auto row = a.AddHStack().Padding(20).Spacing(12);row.UI.AddButton("取消").Margin({0, 0, 8, 0});row.UI.AddButton("保存");

7.4 对齐 Align#

C++
label.Align(Align.Center);button.Align(Align.Right);panel.Align(Align.Fill);

可用值：Free、TopLeft、Top、TopRight、Left、Center、Right、BottomLeft、Bottom、BottomRight、Fill。

规则建议：

  • Align != Free 时，让布局系统决定最终位置。
  • 需要完全自由定位时使用 Align.Free 和 Position()。
  • 不要同时依赖相互冲突的布局约束。

7.5 Grid#

C++
auto grid = a.AddGrid()    .Columns("180,*,Auto")    .Rows("Auto,*,80")    .Padding(24)    .Spacing(12); grid.UI.AddLabel("导航").Row(0).Column(0);grid.UI.AddLabel("标题").Row(0).Column(1).ColumnSpan(2);grid.AddBox().Row(1).Column(0);grid.AddBox().Row(1).Column(1).ColumnSpan(2);grid.UI.AddButton("保存").Row(2).Column(2);
  • 数字：固定像素。
  • Auto：按内容需要。
  • *：分配剩余空间。
  • 2*：获得普通 * 两倍的剩余份额。

容器可用 ChildLayout(Layout.Flow) 做流式排列。子对象可通过 Display(Display.Inline/Block) 和 LineBreak(true) 控制流式布局行为。

31.3 性能原则#

  • 重复图片/精灵共用纹理缓存，不要为每颗子弹生成不同文件。
  • 图集减少纹理切换；同材质、同纹理对象更容易批处理。
  • 不要让每颗子弹对每个敌人手动调用 IsColliding。
  • 静态 UI 不要每帧重设同一属性。
  • Surface.UpdateRegion 优于每次上传整张大画布。
  • 大量文本、阴影、模糊、发光会增加渲染成本。
  • Debug 的 17 FPS 与 Release 的数百 FPS 不能直接比较。

40.1 统一对象模型：句柄、所有权和自动释放#

ToyCode 中的 Button、Image、Sprite、Box 等 C++ 对象是轻量句柄。复制句柄不会复制底层控件，也不会复制纹理：

C++
auto first = a.UI.AddButton("开始");auto second = first;second.Text("继续");     // first和second指向同一个底层按钮

对象树拥有底层对象。父容器释放时，内部子对象一起释放；用户通常不需要 delete，也不应保存裸指针。Dispose() 表示从对象树移除并释放底层对象。句柄本身离开 C++ 作用域并不等于界面对象立即消失，因为父容器仍然持有它。

函数何时使用结果
Valid()使用可能已经释放的句柄前底层对象仍存在时返回 true
GetHandle()编写扩展层或调试底层身份时返回底层句柄；普通业务代码很少需要
Dispose()主动删除子弹、临时提示、已关闭页面等从父容器和事件系统中移除对象
Clear()清空一个容器的全部直接子对象容器本身保留，子对象释放
Remove(child)只移除某一个已知子对象目标离开当前容器并释放

事件闭包由事件属性持有。重新绑定会替换旧闭包，绑定 nullptr 会解除事件并释放旧闭包捕获：

C++
button.Click(nullptr);

不要在匿名函数中引用已经离开作用域的普通局部引用。[=] 捕获 ToyCode 句柄通常安全；[&] 只适用于被引用变量的生命周期明确长于事件的情况。

40.2 Getter、Setter、返回值与链式调用#

同名无参数函数是 Getter，带值函数是 Setter：

C++
Size2D oldSize = panel.Size();panel.Size({600, 400});panel.Width(600).Height(400).Opacity(0.9F);

Setter 返回当前句柄，所以可以继续调用。Getter 返回值是快照；修改快照不会自动写回：

C++
auto size = panel.Size();size.Width += 20;panel.Size(size);              // 必须明确写回

Position()、Size()、Color() 等结构体都提供 ToString()，用于日志和调试，不应用作序列化格式。

40.3 App：应用、主循环和全局服务#

App 是程序入口，也是对象树根节点。创建 App 时还没有 SDL 窗口和渲染器；Run() 才进入平台主循环。因此窗口相关资源预加载可以在 Run() 前登记，但真正上传显存会等渲染器可用后完成。

构造与运行#

C++
App a("星光守卫");a.VirtualSize({1920, 1080});// 创建界面和游戏对象return a.Run();
  • App()：使用默认标题和默认 1920×1080 逻辑尺寸。
  • App(title)：设置初始标题。
  • Run()：创建平台窗口、初始化渲染与音频、触发 Start，然后循环处理输入、更新、布局和绘制，直到退出。
  • Exit()：请求主循环在安全位置结束，不会在事件回调中粗暴终止进程。
  • ToggleFullscreen()：在窗口和全屏状态之间切换。

尺寸和适配#

Size() 是操作系统窗口像素尺寸；VirtualSize() 是代码使用的逻辑坐标。窗口缩放后，ToyCode 根据 ScreenMode() 将逻辑画面映射到实际 Canvas。

模式适合场景代价
ScreenFit.FitUI、横版游戏、希望完整显示比例不同会留边
ScreenFit.Fill背景图和不怕边缘裁剪的场景四周可能被裁剪
ScreenFit.Stretch不关心形变的工具画布横纵比例可能变形
ScreenFit.PixelPerfect像素画可能出现更宽留边

FrameRate() 是不使用垂直同步时的目标更新频率；VSync(true) 后实际帧率通常受显示器刷新率约束。TimeScale() 影响基于 DeltaTime 的动作、物理和动画；它不改变真实系统时间。Paused(true) 用于全局暂停游戏更新，但窗口事件仍需继续处理。

生命周期和定时器#

  • Start(handler)：渲染器和窗口已经可用后调用一次，适合读取依赖窗口的状态。
  • Closing(handler)：退出清理开始前调用一次。不要在这里启动新的长期任务。
  • After(seconds)(handler)：经过指定游戏时间后执行一次。
  • Every(seconds)(handler)：按指定间隔重复执行；回调不保证与真实时钟绝对无误差。

定时器适合 UI 提示、冷却计时和低频任务。角色移动仍应使用 Update 的 DeltaTime，不要用大量 Every(0.016F) 模拟帧更新。

40.4 IBox：所有可视对象共有的能力#

IBox 是视觉树的共同基础。按钮、标签、图片、精灵、形状和容器都继承这些能力。后续控件章节不再重复说明下列成员。

身份与查找#

  • Name()：设置用于查找的逻辑名称，不要求全局唯一，但同一页面内建议唯一。
  • Parent()：取得直接父容器；根对象没有父容器。
  • Child()：返回直接子对象。
  • AllChild<T>()：递归返回指定类型后代；不传类型时取得全部后代。
  • ChildCount()：只统计直接子对象。
  • Find<T>(name)：递归按名称查找并转换为指定句柄类型；找不到时返回无效句柄。
  • Add(child)：将已有对象移动到当前容器末尾。
  • Insert(index, child)：移动到指定子项位置。

不要让两个父容器同时拥有同一底层对象。Add(existing) 的含义是重新挂接，而不是复制一个新控件。

几何属性#

Position() 使用父容器局部坐标，Y 轴向下。Size() 是布局后的目标尺寸。Width()、Height()、X()、Y() 是便捷访问器。MinSize() 和 MaxSize() 约束自动布局结果；Scale() 是绘制缩放，不等价于重新参与 Grid 尺寸计算。

AutoSize(true) 允许对象根据内容计算理想尺寸。图片没有显式尺寸时采用资源原始尺寸；Label 根据文字和字体计算；容器根据子对象、Padding 和 Spacing 计算。显式设置 Width/Height 后，相应方向通常不再由内容决定。

显示状态#

  • Visible(false)：不绘制，也不参与命中测试；是否保留布局空间由 Display 和布局实现决定。
  • Enabled(false)：仍然显示，但不响应交互，适合禁用按钮。
  • Focused()：读取当前键盘焦点；对 TextBox 等可聚焦控件更有意义。
  • Opacity()：范围通常为 0～1，会与父级透明度相乘。
  • ZIndex()：只决定同一视觉层级附近的前后顺序，不改变父子关系。
  • FixedToScreen(true)：忽略 Camera2D，适合 HUD、菜单和调试信息。

背景、边框和状态外观#

Background、Border、BorderWidth、CornerRadius 决定基础外观。HoverBackground、PressedBackground、HoverOffset、PressedOffset 只在对应交互状态生效。普通 Box 和 Label 默认不应因为鼠标经过自行变色；只有设置状态属性后才出现状态变化。

Shadow/ShadowOffset/ShadowBlur 创建投影；Glow/GlowBlur/GlowSpread 创建外发光；BackdropBlur 模糊对象后方已经渲染的内容。大面积模糊和多层阴影比纯色矩形昂贵，移动端和 Web 应控制数量。

布局属性#

  • Padding()：父容器边界到子内容的内部空白。
  • Margin()：当前对象与父布局分配区域边缘之间的外部空白。
  • Spacing()：容器相邻子对象之间的统一间距。
  • Align()：当前对象在父分配区域内的位置和拉伸方式。
  • ChildLayout()：当前容器如何排列子对象。
  • Display()：对象在 Flow/Inline 布局中的参与方式。
  • LineBreak()：在流式布局中要求该对象后换行。
  • Row()、Column()、RowSpan()、ColumnSpan()：对象位于 Grid 的单元格位置。

自由坐标和布局可以共存，但必须知道谁拥有最终位置：Align.Free 时 Position() 生效；非 Free 对齐时布局可能覆盖 Position。游戏场景常用自由坐标，应用界面优先布局。

滚动、裁剪和拖动#

Scrollable(true) 开启滚动范围计算；Scroll() 读取或设置偏移；ScrollStep() 是滚轮步长；ScrollBar(true) 显示滚动条；DragScroll(true) 允许拖动内容滚动；Clip(true) 裁掉容器外内容。只有内容尺寸超过视口时才有可滚动距离。

Draggable(true) 是移动对象本身，不等于 DragScroll。拖动对象时可以监听 Drag；做滑块或地图编辑器时应区分“拖对象”和“拖视口”。

碰撞属性#

Collider() 选择 Box、Circle 等碰撞形状；CollisionOffset() 和 CollisionSize() 允许碰撞范围与图片视觉范围不同。未启用 Collider 的普通 UI 不参与游戏碰撞。

40.5 容器与布局#

Box、VStack、HStack和Flow#

AddBox() 创建通用容器。AddVStack() 与 AddHStack() 是预设了纵向、横向 ChildLayout 的 Box。它们仍然拥有全部 IBox 属性，因此可以设置圆角、背景、边框和滚动。

ChildLayout(Layout.StackVertical) 从上到下排列；StackHorizontal 从左到右；Flow 在空间不足时自动换行；Free 保留子对象自由坐标。布局在内容或尺寸变化后会自动标记为脏并在下一帧重新计算，不需要用户手工调用 Layout。

Grid#

Columns(text) 和 Rows(text) 接受逗号分隔定义。固定数值先分配，Auto 根据内容测量，星号获得剩余空间。RowSpacing()、ColumnSpacing() 可分别控制方向间距；普通 Spacing() 可作为统一默认值。

C++
auto grid = a.AddGrid().Columns("220,*").Rows("Auto,*");grid.UI.AddLabel("项目").Row(0).Column(0);grid.UI.AddTextBox().Row(0).Column(1);grid.AddVStack().Row(1).Column(0).ColumnSpan(2);

Grid 子项没有设置 Row/Column 时默认进入 0,0，多个对象会重叠。动态生成表格时要明确设置行列。

XML布局#

AddLayout(xml) 解析 XML 并返回根 Box。XML 属性最终走同一套属性系统，因此加载后仍可通过 Find<T>() 取得对象并继续链式设置。XML 只描述对象树和初始属性，不应把复杂游戏逻辑写进 XML。

40.6 事件与输入#

事件属性既可以绑定匿名函数，也可以绑定 nullptr。重复绑定同一事件表示替换，不会同时保留多个处理器。需要多个响应时，在一个处理器内调用多个函数，或者自行维护回调列表。

指针事件#

Click 是完整按下和松开形成的点击；Press 在按下瞬间触发；Release 在松开时触发；Enter/Leave 反映命中区域边界变化；Move 反映指针移动；Drag 只在按住移动时触发。PointerArgs 提供发送者、位置、移动量和按键等信息。

菜单、弹窗等覆盖层应阻止命中继续落到底层对象。需要手工创建覆盖层时，应确保覆盖层可命中且 ZIndex 高于背景。

Update#

Update(UpdateArgs) 每帧触发。DeltaTime 是上一帧到当前帧的秒数：

C++
player.Update([=](auto e){    player.X(player.X() + 300.0F * e.DeltaTime);});

不要按“每帧移动 5 像素”编写与帧率绑定的逻辑。暂停或窗口阻塞后，框架会尽量限制异常大的 DeltaTime，但游戏代码仍应避免一次跨越太远。

KeyboardInput#

  • IsDown(key)：当前帧是否按住，适合连续移动。
  • IsPressed(key)：本帧刚按下，适合跳跃、菜单确认。
  • IsReleased(key)：本帧刚松开。
  • Down(key)(handler)：每次物理按下触发一次，不随系统键盘重复连续触发。
  • Up(key)(handler)：松开触发。
  • Hold(key, interval)(handler)：按住后按指定间隔重复触发。
  • Chord(keys)(handler)：组合键满足时触发。

钢琴键、跳跃和菜单按钮使用 Down/IsPressed；飞机连续发射使用 Hold；移动使用 IsDown。不要用 Down 做每帧移动，也不要用 IsDown 播放每帧一次的声音。

40.7 文本、字体和富文本#

Label#

Text() 设置 UTF-8 文本；FontSize() 使用逻辑像素；Font() 选择通过 App.Fonts 或资源加载的字体；Bold()、Italic()、Underline() 控制模拟样式；TextColor()、TextAlign()、LineSpacing()、Wrap() 控制排版。

文字首次出现时会栅格化并缓存为纹理。普通缩放会放大已有纹理，所以过度放大可能变模糊；需要大字时应直接提高 FontSize()。真正的粗体字体文件通常比算法模拟粗体清晰。

Label 支持轻量标记，例如 <b>、<i>、<u> 和 <color=#RRGGBB>。标记适合一段文字内的简单样式；需要图片、嵌入控件和复杂段落时使用 RichText。

FontFamily#

字体族用于给 Regular、Bold、Italic、BoldItalic 分别绑定文件。框架按所需样式选最合适文件，找不到时才模拟。AddFont/字体资源登记应在创建大量文本前完成，以免同一文字因为字体切换重复生成缓存。

RichText#

RichText 是段落容器。AddText() 添加文本片段，AddImage() 添加行内图片，AddBox() 或插入已有 IBox 可嵌入自定义控件。每个片段可以拥有独立颜色、字体和装饰。Clear() 清空内容但保留 RichText 本身。

RichText 适合教程、IDE 帮助、图文说明；不适合用来显示每帧变化的数千段战斗数字。高频短文本优先复用 Label。

40.8 基础控件#

Button#

Button 自带可点击命中、键盘焦点和默认交互外观。Text() 设置内置标题；如果需要图标和复杂排版，也可以向 Button 添加 Label、Image 或 HStack。Default(true) 可表示回车默认按钮，Cancel(true) 可表示 Esc 取消按钮；具体键盘行为应与当前 View 焦点配合。

HoverOffset 和 PressedOffset 是通用 IBox 属性，不只 Button 可用。图片按钮也可以设置它们。PressedOffset 通常设置 {0, 2} 或 {2, 2}，模拟按下，不建议移动过大。

CheckBox、RadioButton和ToggleSwitch#

三者都通过 Checked() 或 IsOn() 表示状态并在值变化后触发 Change。CheckBox 允许独立多选；RadioButton 使用相同 Group() 的项目互斥；ToggleSwitch 适合开关设置。程序调用 Setter 改值时是否触发 Change 应按控件约定处理，避免在 Change 内无条件再次设置同值形成循环。

Slider、NumberBox和ProgressBar#

Min()、Max() 定义范围，Step() 定义离散步长，Value() 会被限制到范围内。Slider 适合拖动；NumberBox 适合精确输入、键盘上下和鼠标拖动；ProgressBar 通常只显示，不接收用户输入。

修改 Min/Max 后，已有 Value 可能被重新限制。百分比显示时可以用 0～100；游戏内部比例更适合 0～1，但必须保持 UI 与业务一致。

ComboBox和ListBox#

Items 管理字符串项目；Add()、Insert()、Remove()、Clear() 修改列表；SelectedIndex() 和 SelectedText() 读取或设置选择；选择改变后触发 Change。索引从 0 开始，-1 表示未选择。

ComboBox 的高亮项会随鼠标移动改变视觉状态，但只有点击或键盘确认后才成为正式选择。ListBox 可始终显示列表。大量动态数据应避免每帧 Clear 后重新添加。

40.9 复合控件和菜单#

SplitView#

SplitView 管理两个面板和中间分隔条。First()、Second() 取得面板容器；Value() 或分割位置控制比例/像素位置；Orientation() 控制横向或纵向；MinFirst()、MinSecond() 防止拖动后某侧过小。分隔条应有清晰悬停反馈和鼠标光标。

TabView#

AddTab(title) 创建标签页并返回页面容器；SelectedIndex() 选择当前页；Count() 返回页数；RemoveTab() 删除页；Change 在用户切换页后触发。页面内容只需创建一次，切换时不要反复重建昂贵资源。

Expander#

Expander 用 Header 和 Content 组成可折叠区域。Expanded() 控制状态，Change 通知展开/收起。折叠通常隐藏内容但保留对象和状态，适合设置面板。

TreeView#

AddNode(text) 创建根节点；节点可继续 AddNode 形成层级。节点支持 Expanded、Selected、图标、用户数据和 Click/Change。删除父节点会同时释放后代。节点名称与路径应由业务层维护，不要把显示文字当唯一数据键。

Menu、MenuItem和ContextMenu#

MenuItem 可以设置 Text、Icon、Shortcut、Checked 和 ToggleKind，也可以继续添加子项。含子项的菜单在鼠标悬停时展开；叶子项点击后触发 Click 并关闭菜单树。ContextMenu 绑定到目标对象后由右键打开。

图标应使用 Image/SVG 资源，而不是依赖某个 Unicode 字符。没有图标的菜单项仍预留统一图标列，从而保证文字对齐。Separator 只用于分组，不接收 Click。

40.10 Image、Shape、SVG和Surface#

Image资源流程#

Source(path) 设置逻辑资源名。框架先通过 Assets 查找独立文件和 ZIP，再通过图片解码器读取像素，最后由 TextureManager 建立共享纹理。同一路径和相同处理参数会尽量复用缓存；再次 AddImage("aa.png") 不会重新从硬盘创建一份完全独立纹理。

SourceRect() 使用原图像素坐标裁剪图集。设置后 Size 默认可按裁剪区域计算，而不是整张大图。Fit() 决定纹理如何放入控件矩形：Contain 完整显示可能留空，Cover 填满可能裁剪，Fill 拉伸，None 保持原尺寸。

Smooth(false) 使用最近邻采样，适合像素画；Smooth(true) 使用平滑采样，适合照片和一般 UI。Color() 是乘色，不会简单覆盖 PNG；透明像素仍透明。HoverColor() 和 PressedColor() 在交互状态替换乘色。FlipX()、FlipY() 镜像绘制，Rotation() 围绕对象锚点旋转。

抠色透明#

MakeTransparent(true) 开启颜色键；TransparentColor() 指定被扣除的颜色；未指定时可采用左上角像素；TransparentTolerance() 控制颜色差容忍度；TransparentSoftness() 在边缘生成半透明过渡。它适合纯色背景 JPG，不等同于真正带 Alpha 的 PNG，复杂背景会出现误删。

Shape和Path#

Circle、Rectangle、Line 是轻量矢量形状，适合简单 UI 和调试图。Path/SVG 适合图标和复杂曲线。形状的 Fill、Stroke、StrokeWidth 等属性由渲染器直接绘制；SVG/Path 通常先栅格化到合适尺寸并缓存，尺寸大幅改变时可能重新栅格化。

Surface#

Surface 是可更新像素纹理。Clear、DrawLine、FillRect、FillCircle、FillTriangle 修改 CPU 侧画布；Update(pixels,w,h) 上传整张；UpdateRegion(rect,pixels) 只上传局部。频繁逐像素跨 API 调用较慢，推荐在内存数组中一次生成后批量 Update。

40.11 Sprite与序列帧状态机#

Sprite 在 Image 基础上增加固定帧网格、动画片段和状态机。

  • FrameSize()：每格像素尺寸。
  • Grid()：图集列数和行数；通常可由纹理尺寸与 FrameSize 推导。
  • FrameIndex()：当前帧编号。
  • AddAnimation(name, frames, fps, loop)：定义命名片段，不会立即播放。
  • RemoveAnimation(name)：删除定义；正在播放该动画时应先切换或停止。
  • Play(name)：从片段起点播放。
  • Pause()/Resume()：保留当前帧暂停或继续。
  • Stop()：停止并回到约定的初始状态。
  • Restart()：从当前动画第一帧重新播放。
  • Animation()、IsPlaying()、IsPaused()：查询状态。
  • Speed()：播放倍率，1 为原速。

Frame 在帧索引真正变化时触发，不应假设每个渲染帧都触发。攻击判定通常绑定到指定动画帧：

C++
knight.Frame([=](auto e){    if (e.Frame == 1)        swordHitbox.Enabled(true);    if (e.Frame == 2)        swordHitbox.Enabled(false);});

End 在非循环动画结束时触发；循环动画每轮是否触发 End 取决于循环语义，业务上更稳妥的是用 Frame 检测首帧或显式状态切换。AddState 将逻辑状态映射到动画，SetNextState 定义完成后的自动状态，State() 执行切换。

40.12 Action动作系统#

Action 修改对象属性，但不取得对象所有权。对象被 Dispose 后，挂在对象上的动作自动停止。

串联和并联#

连续调用动作表示串联；Both() 到 EndBoth() 表示并联；Do() 编译并启动整条动作。如果遗漏 EndBoth，Do 会闭合当前并联组，但建议代码仍明确写出以便阅读。

时间与速度#

MoveBy(distance, seconds) 指定持续时间；MoveBy(distance, Speed{value}) 按距离和速度计算持续时间。速度为 0 或负值属于无效输入。固定速度适合角色和子弹，固定时长适合 UI 动画。

动作函数#

Wait 只延迟序列；MoveTo/MoveBy 修改位置；FadeTo 修改透明度；ScaleTo/ScaleBy 修改缩放；RotateTo/RotateBy 修改角度；JumpTo/JumpBy 在位移上叠加抛物线高度；Blink 切换可见性；Repeat(count) 重复前一段或组合；Loop() 无限循环。

Ease.Linear 匀速，In 慢起快收，Out 快起慢收，InOut 两端平滑。游戏物理移动不建议用视觉缓动代替物理速度。

Pause、Resume、Stop 控制当前对象动作；End 只在自然完成时触发还是 Stop 也触发，应以“取消不等于完成”为原则编写，清理逻辑不要只依赖 End。

40.13 碰撞与轻量物理#

IsColliding(other) 是一次即时几何查询，适合少量对象和调试。N 颗子弹逐个检查 M 个敌人会产生 N×M 次测试。CollisionEvents/PhysicsManager 应使用空间分区处理大量对象。

Collision(other).Enter 在不相交变为相交时触发一次；Stay 在持续相交期间每个物理更新触发；Leave 在相交变为分离时触发一次。删除任意对象会终止对应关系，不应依赖删除后一定再收到 Leave。

BodyController 的 Dynamic() 让物体受速度和重力影响，Static() 表示固定障碍；Velocity() 设置线速度；Gravity() 可覆盖全局重力；Bounce() 控制反弹；Friction() 控制接触切向衰减；Mass() 影响动力响应。直接设置 Position 会瞬移，可能绕过连续碰撞；高速子弹应启用更合适的检测方式或缩小时间步长。

40.14 Particles粒子系统#

Particles 用一个发射器管理大量短生命周期粒子，不为每颗粒子创建完整 IBox，因此比创建数千个 Circle 更高效。

Rate() 是每秒发射数量；Life() 是单粒子寿命；Duration() 是发射器持续时间；Loop() 决定结束后是否重新开始；MaxCount() 是内存与性能上限。Speed()、Direction()、Spread() 决定初速度；Gravity()、Drag() 影响运动；StartSize/EndSize、StartColor/EndColor 控制生命周期插值。

Shape() 决定初始位置分布，Style() 决定 Square/Circle/Glow 等外观，Blend(Add) 适合火焰和魔法光，Alpha 适合烟尘。Texture() 可让粒子使用图片；相同图片共享纹理缓存。

Play 开始按 Rate 发射；Emit(count) 立即爆发；Pause/Resume 保留现有粒子；Stop 停止发射；Clear 立即删除当前粒子；Replay 清理后重新开始。ParticleCount() 用于调试，不应每帧据此创建复杂 UI。

40.15 TileMap#

TileMap 用一张图集和二维整数数组表示地图。MapSize() 是图块数量，不是像素尺寸；实际像素尺寸约等于列数×TileWidth、行数×TileHeight。

SetTile/GetTile 修改或读取单格；Fill 填满地图；DrawLine 画图块线；FloodFill 从指定格开始填充相邻同值区域。越界坐标不会成为有效图块，编辑器应检查返回结果。

ToTile(pixel) 把地图局部像素转成格坐标；ToPosition(col,row) 返回格子左上角；ToCenter 返回中心。世界坐标还需考虑 TileMap 自身 Position 和相机变换。

SetBlocked/IsBlocked 管理通行数据；FindPath 使用格坐标；FindPathAt 使用局部像素坐标；Follow 让对象沿路径移动。寻路结果可能为空，表示不可达，调用 Follow 前应判断。

AddAnimation(tile, frames, fps) 让某个逻辑图块循环显示帧；它不会修改地图数组。Save/Load 保存地图数据和必要配置，但外部图集仍是独立资源。

40.16 Lottie#

Source() 指向 Lottie JSON；Play/Pause/Resume/Stop/Restart 控制时间线；Loop() 控制循环；Speed() 是倍率；Progress() 通常表示 0～1 归一化进度；Duration() 是资源时长；IsPlaying/IsPaused 查询状态。

Color() 是统一着色覆盖，适合单色图标动画。多层渐变和图片资产不一定能完整改色。Lottie 通常按显示尺寸栅格化，持续大幅缩放会增加重绘成本。End 对非循环播放最有意义。

40.17 Audio、Music和Sound#

Assets 先定位文件，音频解码器把 WAV/OGG/MP3 转成共享 PCM 缓存，Music/Sound 是独立播放实例。

a.Audio.Preload(path) 提前读取解码；批量重载接受初始化列表；IsLoaded 查询缓存；Count 返回缓存条目数；ClearUnused 只删除没有存活播放对象引用的条目。Volume 是总音量，MusicVolume 和 SoundVolume 是分类音量，最终音量还会乘以每个实例自己的 Volume。

Music 适合长背景音乐和循环；Sound 适合短音效和快速重复。每个实例的 Play/Pause/Resume/Stop 独立。全局 a.Audio.Pause/Resume/Stop 作用于全部实例。重复播放同一个 Sound 可以重触发/叠加的具体策略由播放实现决定；需要严格多声道时可创建多个 Sound 句柄，但它们仍共享 PCM。

OGG 必须是 Vorbis 编码，容器扩展名本身不能保证可解码；MP3 应采用常见 Layer III；WAV 可能包含多种编码，最稳妥的是 PCM。

40.18 Assets与Textures#

Assets.AddZip(path) 把 ZIP 加入搜索列表；Exists(name) 检查资源是否能从独立文件或已登记 ZIP 找到；Where(name) 返回实际文件路径或 ZIP 描述，找不到返回空字符串。ZIP 中多压一层目录时，逻辑名称也必须包含该层目录。

a.Textures.Preload 是二维纹理缓存；IsLoaded 表示已经解码并上传；Count 是缓存纹理数；ClearUnused 删除没有 Image、Sprite、TileMap 或粒子引用的纹理。不要在每帧调用 ClearUnused，适合关卡切换后调用。

全局 Textures.Load/Checker 是 3D Texture3DFactory，与 a.Textures 无关。其他 AI 生成代码时必须区分这两个名字。

40.19 View、Camera2D和调试#

View 是主窗口中的页面/场景。Show(view, transition, seconds) 显示并把旧 View 放入历史；Back 返回；CanBack 判断；ClearHistory 清空。不要把 View 当操作系统多窗口。

Camera2D 的 Position 是观察中心/偏移，Zoom 控制世界缩放，Rotation 控制场景旋转。HUD 使用 FixedToScreen(true)。相机只改变绘制和输入坐标映射，不应直接修改所有游戏对象坐标。

Debug.Stats(true) 显示 FPS、Update、Layout、Render、Objects、Batches、Textures 等；Performance() 返回结构化统计；碰撞框、布局边界等开关只用于调试。性能判断应使用 Release x64，并关注 Render 与 Layout 的实际耗时，而不是只看 FPS。

40.20 轻量3D#

World3D 是渲染到 ToyCode 对象树中的轻量 3D 世界。AddWorld3D(width,height) 创建世界及其 Canvas；Camera3D 使用 Position、LookAt、Fov、近远裁剪面；DirectionalLight3D 使用 Direction、Color、Ambient、Strength。

AddCube/AddPlane/... 创建基础 Mesh；LoadObj 加载 OBJ；Mesh3D 的 Position/Rotation/Scale/Visible/Mode/Material 控制实例。Material3D 包含 Color、Texture 和光照参数。多个 Mesh 可以共享 Texture3D 和 Material 数据，减少重复内存。

Textures.Load(path) 加载 3D 图片纹理；Textures.Checker(...) 创建程序棋盘纹理。World3D 的 Update 适合旋转模型和游戏逻辑；属性变化后由世界渲染，不应为了静态场景每帧重建 Mesh。

当前 3D 不等于完整大型引擎：骨骼动画、glTF、复杂物理、遮挡剔除和大型编辑器属于后续范围。

40.21 Tools#

Tools.Time 提供运行时间、真实时间和格式化；Tools.Rand() 提供 0～1 随机小数，Tools.Rand(min,max) 根据参数类型生成整数、float 或 double，Tools.Seed(value) 设置种子。需要可复现关卡时应显式设置种子；视觉粒子可使用随机种子。

Clipboard 读取和写入文本；Web 平台可能要求用户手势和浏览器权限。File 读取/写入文本和字节；Path 负责组合、扩展名、文件名和规范化；Folder 创建、判断和枚举目录。资源读取优先 Assets，用户存档才使用 File/Folder。

40按模块编写游戏的完整示例#

下面的骨架展示布局、资源预加载、精灵、输入、动作、碰撞、音效和页面如何配合。它不是固定模板，但能帮助 AI 理解对象之间的职责。

C++
#include <ToyCode.h>using namespace toy; int main(){    App a("星光守卫");    a.VirtualSize({1920, 1080});    a.ScreenMode(ScreenFit.Fit);    a.Background(Colors.Sky.Lighter());     a.Assets.AddZip("assets.zip");    a.Textures.Preload({"player.png", "enemy.png", "bullet.png"});    a.Audio.Preload({"shoot.wav", "hit.ogg", "music.mp3"});     auto game = a.AddView();    auto hud = game.AddHStack().Align(Align.Top).Padding(24).Spacing(20).FixedToScreen(true).ZIndex(100);    auto scoreText = hud.UI.AddLabel("分数：0").FontSize(32);    auto lifeText = hud.UI.AddLabel("生命：3").FontSize(32);     auto player = game.AddSprite("player.png", 96, 96).Position({912, 850}).Collider(ColliderShape.Box);    player.AddAnimation("idle", {0, 1, 2, 3}, 8, true);    player.Play("idle");     auto shoot = a.AddSound("shoot.wav").Volume(0.8F);    int score = 0;     player.Update([=](auto e) mutable    {        Vec2 p = player.Position();        if (a.Keyboard.IsDown(Keys.Left))  p.X -= 520.0F * e.DeltaTime;        if (a.Keyboard.IsDown(Keys.Right)) p.X += 520.0F * e.DeltaTime;        p.X = std::clamp(p.X, 0.0F, 1920.0F - player.Width());        player.Position(p);    });     a.Keyboard.Hold(Keys.Space, 0.12F)([=](auto e)    {        auto bullet = game.AddImage("bullet.png").Position({player.X() + 40, player.Y() - 24}).Collider(ColliderShape.Circle);        bullet.Action.End([=](auto e)        {            bullet.Dispose();        });        bullet.Action.MoveBy({0, -1200}, Speed{900}).Do();        shoot.Play();    });     a.Every(1.0F)([=](auto e) mutable    {        auto enemy = game.AddImage("enemy.png").Position({a.Tools.Rand(0.0F, 1820.0F), -100}).Collider(ColliderShape.Box);        enemy.Action.End([=](auto e)        {            enemy.Dispose();        });        enemy.Action.MoveBy({0, 1300}, Speed{180}).Do();    });     a.Show(game);    return a.Run();}

实际项目应把生成敌人、生成子弹、结算碰撞分别封装成普通 C++ 函数或类。ToyCode 简化的是界面、资源和游戏对象操作，并不禁止使用标准 C++ 组织大型代码。

41供其他AI生成ToyCode代码的约束#

  1. 只使用本文档中存在的类型和函数，不根据其他引擎猜测 Scene、Node、GameObject、Destroy 等 API。
  2. 程序从 App a; 开始，以 return a.Run(); 结束。
  3. UI 控件优先使用 a.UI.Add...；形状使用 a.Shape.Add...；普通容器、图片、精灵、粒子和 3D 世界使用 a.Add...。
  4. 使用 Getter/Setter：x.Size() 读取，x.Size(value) 设置；不要生成 .Get() 或公开字段赋值。
  5. UI 排版优先使用 VStack、HStack、Grid、Padding、Margin、Spacing 和 Align；游戏对象才优先使用 Position。
  6. 事件写成 button.Click([=](ClickArgs e) { ... });；需要 IntelliSense 时写明确 Args 类型。
  7. 每帧移动必须乘 e.DeltaTime。
  8. 父对象拥有子对象；通常不手工释放。主动删除临时对象使用 Dispose()，不要写 delete。
  9. 图片使用 a.Textures 缓存，文件和 ZIP 使用 a.Assets，音频使用 a.Audio；不要创造 Resources。
  10. a.Textures 是二维缓存；全局 Textures 是 3D 纹理工厂。
  11. 同一路径资源自动共享缓存，不要为了复用纹理自行维护裸 SDL_Texture 指针。
  12. 大量碰撞不要进行所有对象两两 IsColliding。
  13. View 是主窗口内页面，不是原生多窗口。
  14. Release x64 才用于正式性能判断。
  15. 如果某个函数的行为在本文档没有说明，应询问用户或检查当前 ToyCode 版本，不应虚构重载。
